# D/E楼巡检数据处理

## 入口与调度

- 内网分别提供两份即时报表，名称必须完全匹配“电气巡检表”和“暖通巡检表”。每份覆盖D/E楼，查询当前时间前20分钟至当前时间，刻度为5分钟，不填写配置sheet。两项内网自动采集均保持关闭。
- 外网专项任务“巡检数据处理”保留手动上传和手动 `dry_run`。上传调度保持关闭：`enabled=false`、`auto_start_in_gui=false`、`run_times=[]`；本次接入不启用自动调度或写入调度时间。
- 外网仅通过HTTP source-index取得明确文件路径，不扫描共享目录。必须同时具备D楼电气、D楼暖通、E楼电气、E楼暖通四份独立文件，旧 `inspection_data_family` 合并文件不能兜底，也不能将同一路径登记为多份文件。
- 两个来源均使用 `bucket_kind=latest`、`bucket_key=YYYY-MM-DD HH`。只使用所选日期的最新登记文件；当前日期文件超过120分钟会等待补采。最新登记文件不可访问时不回退到更旧文件。
- 缺失或过期时，仅按对应专业和缺失楼栋发起补采；请求失败时只重试尚未成功提交的组合。已提交的同小时组合等待索引就绪，不重复提交；历史日期缺失直接报错，不补采当前时刻代替历史数据。

| 专业 | 报表名称 | source_family | 标签 |
| --- | --- | --- | --- |
| 电气 | 电气巡检表 | `electrical_inspection_family` | 电气巡检源文件 |
| 暖通 | 暖通巡检表 | `hvac_inspection_family` | 暖通巡检源文件 |

默认配置使用 `source_families={"电气":"electrical_inspection_family","暖通":"hvac_inspection_family"}`，不再使用单数 `source_family`。服务固定使用上述对应关系，旧配置或交叉映射不能改变实际取源专业。

- E楼：`ASLxbfESPahdTKs0A9NccgbrnXc / tblbkTs8tfW869ry`

- 目录包含D楼458个、E楼521个对象，2151个表内测点。原表来源、工作表、设备单元格、指标单元格均保存在 `app/modules/inspection_data/data/inspection_catalog.json`。

- “上传日期”为本次上传时间，“源文件时间”为该设备所属专业文件的内网下载登记时间，“源文件”也只填写该专业文件名，两者不混用。

## 两份动环报表格式

两份报表的第一张工作表均使用与交接班源文件相同的纵向结构：

| 列 | 内容 | 示例 |
| --- | --- | --- |
| B | 位置 | 电气系统西区 |
| C | 设备编号 | D-144-TR-101 |
| D | 点位名称 | L1温度(℃) |
| E起 | 各时刻数值或状态，列头为时刻 | 2026-10-27 09:00:00 |

- B/C可使用合并单元格，空白行沿用上一条位置和设备；位置改变时不会沿用上一位置的设备。
- 多时刻数据固定选取最靠左的时间列，不取最大值、平均值等统计列。该时刻无效或为空时留空，不改取后续时刻。旧式只有E列数值的文件仍读取E列；多列无时间表头时拒绝上传，避免错取。
- 点位名称采用点位目录中的 `field`，或该对象原表中完整指标名称。三相指标必须明确L1/L2/L3，不能用一个“温度”替代三个相位。
- 同名CRAH01等设备必须同时提供目录中的位置；也支持原表房间号组合后的完整编号，例如 `D-240-CRAH-01`。
- “启停状态”使用明确的1/0或开启/关闭、运行/停止；1为开启、0为关闭。不从“无告警”“远程控制”“开关正常”推断设备正在运行。
- 表内有无滴漏、有无存油等人工项目如无动环点位，保留空白并列入“缺少源数据”，不伪造正常值。
- 不明确、无法解析的数值留空，不变为0；真正的数值0正常上传。同一对象同一指标出现冲突值时停止上传，避免错取。

### API 缺点与分组

- 暖通将离散状态点与其余测点分两组查询，查询窗口相同；两组真实采样时刻必须一致。响应超过大小限制时，只拆分超限的组，不重拉另一组。
- 有明确请求 ID、返回身份正确且有真实读数时，内网将未返回的 ID 追加到快照，并用 `zero_filled_point_ids` 列出；仅占位值为字符串 `"0"`。请求超时、重复或额外 ID、错时段等不按缺点处理。外网不会替不完整的传输快照补行。
- 已返回 ID 但该轮读数缺失时，单独记录在 `zero_filled_sample_point_ids`，设备/指标名保留，仍不能把占位当成实测。
- 数值占位与真实零在结果表中有区别：占位明细标记“缺少源数据”，原始值和采样时间留空，不参与修正或设备联动。状态占位为“待核对”，不能据此填写停机三角形；实测停机才按本设备本轮填写。
- 共享源文件登记就绪后，内网会将缺测提醒交给外网群机器人。测点过多时分条发送，缺测明细也保留在源文件；提醒发送失败不改变源文件状态，也不影响数据上传。待发提醒可在 24 小时内补发，超过 24 小时不再向群里发送旧提醒。

## 结果元数据

- 两楼都参与时，手动 `dry_run` 与上传成功结果均返回 `source_file_count=4` 及上述 `source_families` 映射。`dry_run` 会核验飞书测点配置、读取并解析本轮来源，不写入或删除目标表记录。
- `results["D楼"].sources` 和 `results["E楼"].sources` 分别以两个 family 为键。每个值包含 `discipline`、`report_name`、`label`、`source_family`、`source_file`、`source_time`、`bucket_kind`、`bucket_key`，以及该文件自己的 `value_column`、`value_time`、有效测点数和解析诊断。
- `results[楼栋].sources[family].source_time` 是该专业实际采用的采样时刻，常规采集取窗口内第一个时刻，按需最新采集取最新时刻；电气和暖通分别保留。

## 替换与失败保护

1. 对参与本次上传的每一楼栋，电气、暖通的来源都要读取、解析成功，并通过目标表字段校验。
2. 先校验旧记录 ID，保存本地 `.runtime/inspection_data/backups/` 快照。重试遇到 `pending` 快照时保留失败前原数据。
3. 先批量创建新记录，核对记录 ID 集合及实际字段。所有参与楼栋的新批次核验通过后，才按楼删除先前记录的 ID，并再次回查，最后写入完成标记。
4. 任一专业没有可识别测点、任一文件缺失、字段类型冲突、旧记录ID不完整或快照保存失败时，都不清空目标表。
5. 新批次校验失败时保留旧记录，并尝试清理本次暂存记录。删除旧记录或写完成标记时中断可能造成两批暂时并存或批次未确认；调用方须核验完成标记，不能以看见新记录作为成功依据。
6. 其他业务表和四份原始巡检模板不修改。

## 字段初始化

在外网端目录执行：

```powershell
python -m app.modules.inspection_data.cli --config 表格计算配置.json
python -m app.modules.inspection_data.cli --config 表格计算配置.json --apply-schema
```

第一条只检查；第二条只创建缺少的字段，不删除字段或业务记录。统一使用配置中心 `common.feishu_auth`，不增加独立应用凭证。

## 灯塔：固定值、手工状态与区间判定

测点配置仍走 D/E 楼原有配置接口。后台核验和上传任务按楼共用最近 5 分钟内完整核验的配置，重启后可复用；到期核验失败时只保留该楼原配置和旧巡检数据，不用过期配置发布。直接在飞书修改的配置由后台在到期后识别，也可请求 `/api/scheduler/inspection-data-upload/points/{building_code}?fresh=true` 立即核验。审核页保存会重新核验飞书，确认成功后立即更新缓存。

非采集项在 `points`、`targets` 和 `status_rules` 中使用相同的 `local_<32位小写十六进制>` 内部 ID，由配置页自动生成，编辑时保持不变。批量配置客户端可生成并持久化同格式 ID，不应向用户索要采集 ID。非采集项不会出现在内网 `baseline/add/remove` 清单中。

| 新增文本字段（配置表和结果表） | 值 |
| --- | --- |
| 测点来源 | 空或 `collected` 为内网采集；`fixed_status` 为固定状态；`fixed_value` 为固定数值；`manual_status` 为手工巡检状态 |
| 固定值 | 固定状态为 `√`、`×` 或 `△`；固定数值为十进制文本；其余留空 |
| 状态区间规则 | JSON 数组，如 `[{"min":"0","max":"1.5","status":"normal"}]`；状态枚举 `normal`、`abnormal`、`not_running` |

- API 中对应字段位于 `status_rules[id]`：`source_kind`、`fixed_value`、`intervals`。固定数值用 `type: "直接填充"`；固定状态和手工状态用 `type: "状态"`。非采集项仍绑定工作簿、工作表及单轮或四轮目标格；暖通冷机系统最多一个不同的目标格。
- 采集值先用现有数值修正规则得出有效值，再按原有文本精确映射、数值闭区间顺序判定。区间相接或重叠，或与其他状态的精确数值冲突时，拒绝保存。原始值为空、不能匹配或解析失败时判为「待核对」。
- 固定/手工项作为 `记录类型=测点明细` 进入本批完整性校验；没有采样时间、采集源文件或原始读数。固定状态用「状态判定」，固定数值用「测点值」，包括数值 0。手工项默认「待核对」，外网不代填、不维护人工选值或覆盖灯塔历史记录；每轮选择和后续沿用由灯塔负责，可按稳定 ID 关联。
- 启用、删除、改目标格或规则后，配置和结果按现有同步及上传流程发布。协调写入方后再启用实际字段创建和数据写入。
