# D/E楼巡检数据处理

## 入口与调度

- 内网分别提供两份即时报表，名称必须完全匹配“电气巡检表”和“暖通巡检表”。每份覆盖D/E楼，查询当前时间前20分钟至当前时间，刻度为5分钟，不填写配置sheet。两项内网自动采集均保持关闭。
- 外网专项任务“巡检数据处理”保留手动上传和手动 `dry_run`。上传调度保持关闭：`enabled=false`、`auto_start_in_gui=false`、`run_times=[]`；本次接入不启用自动调度或写入调度时间。
- 外网仅通过HTTP source-index取得明确文件路径，不扫描共享目录。必须同时具备D楼电气、D楼暖通、E楼电气、E楼暖通四份独立文件，旧 `inspection_data_family` 合并文件不能兜底，也不能将同一路径登记为多份文件。
- 两个来源均使用 `bucket_kind=latest`、`bucket_key=YYYY-MM-DD HH`。只使用所选日期的最新登记文件；当前日期文件超过120分钟会等待补采。最新登记文件不可访问时不回退到更旧文件。
- 缺失或过期时，仅按对应专业和缺失楼栋发起补采；请求失败时只重试尚未成功提交的组合。已提交的同小时组合等待索引就绪，不重复提交；历史日期缺失直接报错，不补采当前时刻代替历史数据。

| 专业 | 报表名称 | source_family | 标签 |
| --- | --- | --- | --- |
| 电气 | 电气巡检表 | `electrical_inspection_family` | 电气巡检源文件 |
| 暖通 | 暖通巡检表 | `hvac_inspection_family` | 暖通巡检源文件 |

默认配置使用 `source_families={"电气":"electrical_inspection_family","暖通":"hvac_inspection_family"}`，不再使用单数 `source_family`。服务固定使用上述对应关系，旧配置或交叉映射不能改变实际取源专业。

- E楼：`ASLxbfESPahdTKs0A9NccgbrnXc / tblbkTs8tfW869ry`

## 两份动环报表格式

两份报表的第一张工作表均使用与交接班源文件相同的纵向结构：

| 列 | 内容 | 示例 |
| --- | --- | --- |
| B | 位置 | 电气系统西区 |
| C | 设备编号 | D-144-TR-101 |
| D | 点位名称 | L1温度(℃) |
| E起 | 各时刻数值或状态，列头为时刻 | 2026-10-27 09:00:00 |

- B/C可使用合并单元格，空白行沿用上一条位置和设备；位置改变时不会沿用上一位置的设备。
- 多时刻数据固定选取最靠左的时间列，不取最大值、平均值等统计列。该时刻无效或为空时留空，不改取后续时刻。旧式只有E列数值的文件仍读取E列；多列无时间表头时拒绝上传，避免错取。
- 点位名称采用点位目录中的 `field`，或该对象原表中完整指标名称。三相指标必须明确L1/L2/L3，不能用一个“温度”替代三个相位。
- 同名CRAH01等设备必须同时提供目录中的位置；也支持原表房间号组合后的完整编号，例如 `D-240-CRAH-01`。
- “启停状态”使用明确的1/0或开启/关闭、运行/停止；1为开启、0为关闭。不从“无告警”“远程控制”“开关正常”推断设备正在运行。
- 表内有无滴漏、有无存油等人工项目如无动环点位，保留空白并列入“缺少源数据”，不伪造正常值。
- 不明确、无法解析的数值留空，不变为0；真正的数值0正常上传。同一对象同一指标出现冲突值时停止上传，避免错取。

本次仅通过模拟客户端和合成文件验证双源契约，未读取真实源报表、未验证动环实际点位名称，也未执行真实飞书写入。正式样本需另行核对解析诊断与缺少源数据清单；自动采集和上传继续保持关闭。

## 结果元数据

- 手动 `dry_run` 与上传成功结果均返回 `source_file_count=4` 及上述 `source_families` 映射。`dry_run` 仅解析与汇总，不创建飞书客户端、不查询目标表、不保存快照、不删除或上传记录；缺源时仍沿用手动补采等待流程。
- `results["D楼"].sources` 和 `results["E楼"].sources` 分别以两个 family 为键。每个值包含 `discipline`、`report_name`、`label`、`source_family`、`source_file`、`source_time`、`bucket_kind`、`bucket_key`，以及该文件自己的 `value_column`、`value_time`、有效测点数和解析诊断。
- `source_time` 是下载登记时间，`value_time` 是实际选取的第一个时间表头；两份文件分别保留，楼栋汇总不再用单个时间掩盖两份来源。

## 替换与失败保护

1. 两楼两专业共四份文件全部读取、分专业解析成功，并且两张表的字段校验通过后才准备替换。
2. 两楼旧记录ID校验和本地 `.runtime/inspection_data/backups/` 快照保存都在首次清空之前完成。重试遇到 `pending` 快照时保留失败前原数据，不用半写入状态覆盖。
3. 按要求清空该楼目标表，再批量上传新记录并回查记录ID数量。
4. 任一专业没有可识别测点、任一文件缺失、字段类型冲突、旧记录ID不完整或快照保存失败时，都不清空目标表。
5. 清空后网络异常仍可能导致目标表暂时不完整。任务明确失败，保留本地快照，重跑重新覆盖；本流程不是飞书事务，不能承诺清空与新增原子完成。
6. 其他业务表和四份原始巡检模板不修改。

## 字段初始化

在外网端目录执行：

```powershell
python -m app.modules.inspection_data.cli --config 表格计算配置.json
python -m app.modules.inspection_data.cli --config 表格计算配置.json --apply-schema
```

第一条只检查；第二条只创建缺少的字段，不删除字段或业务记录。统一使用配置中心 `common.feishu_auth`，不增加独立应用凭证。
